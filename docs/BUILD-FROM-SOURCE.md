# Building Tidy 2.3.1 from source

## Current status

The authored application in `app/src/main/` is a buildable reconstruction, not the recovered original Kotlin project or a byte-identical reproduction of 2.2.0. Historical `sources/`, `bytecode/` and `resources/` are preserved on [archive/2.2.0-reference](https://github.com/faraajs/tidy/tree/archive/2.2.0-reference), removed from main and never compiled. The original 2.2.0 APK remains withheld: its missing preferred application source and unmatched native provenance are not repaired by this new build. See [recovery notes](RECOVERY-NOTES.md) and [third-party notices](THIRD-PARTY-NOTICES.md).

## Prerequisites and commands

Use JDK **17**, Android SDK command-line tools, and these SDK packages:

```sh
sdkmanager 'platform-tools' 'platforms;android-36' 'build-tools;36.0.0' \
  'ndk;27.1.12297006' 'cmake;3.22.1'
```

Accept the SDK licenses as appropriate. Set `JAVA_HOME` to JDK 17 and `ANDROID_HOME` to your SDK outside the checkout (or use an untracked `local.properties` with `sdk.dir`). The wrapper pins **Gradle 9.4.1** and its official distribution SHA-256 in `gradle/wrapper/gradle-wrapper.properties`; the project pins **AGP 9.2.1**. Initial wrapper/plugin/Maven resolution needs network access; this does not give the app runtime network access.

The checked-in wrapper JAR matches the official Gradle `v9.4.1` tag byte-for-byte: SHA-256 `55243ef57851f12b070ad14f7f5bb8302daceeebc5bce5ece5fa6edb23e1145c`. Its Apache-2.0 text is embedded at `META-INF/LICENSE`; the accompanying [Gradle NOTICE](licenses/Gradle-9.4.1-NOTICE.txt) describes build tooling, not runtime components bundled in Tidy.

From the repository or extracted corresponding-source bundle:

```sh
./gradlew assembleDebug testDebugUnitTest assembleDebugAndroidTest --max-workers=2 --no-daemon
./gradlew assembleRelease --max-workers=2 --no-daemon
```

Debug APKs are under `app/build/outputs/apk/debug/`; with no signing configuration, release output is `app/build/outputs/apk/release/app-release-unsigned.apk`. Debug signing is generated by Android build tools, not the historical 2.2.0 key. Neither building an unsigned APK nor a debug APK reproduces the official release signature.

The application is `id.eska.tidy`, namespace `id.eska.screenshotwebp`, version **2.3.1 / 4**, minimum **API 30**, compile/target **API 36**. Both **arm64-v8a** and **x86_64** are built. Java platform Views replace historical Compose-generated code; no recovered assets or opaque native prebuilts are copied into the app.

The published application ID, source namespace and manifest component names intentionally remain unchanged. Aligning `id.eska.screenshotwebp` cosmetically with the app name could invalidate installed component references/grants; it does not improve the build and is not a nonbreaking cleanup.

External libyuv and libsharpyuv are disabled, but libavif's embedded scalar libyuv sources are compiled and retain their notices. No historical HeifCoder/libheif/x265/HEVC chain is used. For AOM, `arm64-v8a` uses baseline NEON and the NDK Clang integrated assembler. Optional ARM CRC32, dot-product, I8MM, SVE and SVE2 extensions remain disabled. `x86_64` uses the generic implementation and does not require NASM. This optimization affects AVIF, not Android's platform WebP codec; dimensions, quality and one codec thread per call are unchanged.

[`native/java-dependencies.json`](../native/java-dependencies.json) identifies the exact matching preferred-source JARs and SHA-256 values for ExifInterface 1.4.2, annotation-jvm 1.8.1, JSpecify 1.0.0, the AGP-resolved Kotlin stdlib 2.2.10 and JetBrains annotations 13.0. ### Conservative NDK runtime preferred sources

The NDK-provided static C++/ABI/unwind/compiler-rt archive portions selected by the native link have additional preferred-source provenance in [`native/compiler-runtime-sources.json`](../native/compiler-runtime-sources.json). This is a conservative runtime-source disclosure, not a full compiler/SDK rebuild project or a claim that GPL requires shipping those tools. See the [GNU System Libraries explanation](https://www.gnu.org/licenses/gpl-faq.html#SystemLibraryException) and [notice/legal boundary](THIRD-PARTY-NOTICES.md#gpl-notices-and-installation-of-modifications).

The manifest identifies immutable LLVM base `3c92011b600bdf70424e2547594dd461fe411a41` and Android `llvm_android` recipes/patch revision `2a4ee244d6dd0dcb8365590b898f7a40ec3cb87a` for NDK `27.1.12297006` / Clang `r522817b`, patch level 2. Source inputs include complete libc++, libc++abi, libunwind and compiler-rt directories, retained LLVM CMake/header/support subtrees, the Android recipes, source information, full notices, exact archive hashes and per-file inventories. All **71 selected original patches** are retained, even where a patch only affects compiler sources outside the runtime subset.

To reconstruct the patched runtime/support source subset from the bundled inputs, use **Python 3.12+** and **GNU patch**, from the extracted source-bundle root, choosing a new output directory:

```sh
python3 .native-sources/toolchain/reconstruct-runtime.py \
  native/compiler-runtime-sources.json /absolute/new-output-directory
```

The script verifies retained runtime inputs and original patches, extracts immutable base sources without changing them, and follows the manifest's `patchesInApplicationOrder`. The manifest selects the 71 patches from `PATCHES.json` in metadata-array order using `version_range.from <= 522817 < version_range.until` (null means unbounded). The alphabetically sorted `clang_source_info.md` list is **not application order**; the manifest records the single `cherry/` patch-link correction. Only complete `diff --git` sections under retained runtime/support subtrees are projected, then applied with `--fuzz=0`, failing on rejected hunks. The recorded source reconstruction applied **21 projected patches** (15 touching runtime directories); exact-context line offsets occurred. This reconstructs source only: no compiler/runtime binary was rebuilt or tested by that procedure.

Correspondence is anchored in the installed NDK source information and its identified official Android recipes, not an independently byte-identical runtime rebuild. Full LLVM compiler sources/binaries, bootstrap/build environment and prebuilt SDK/sysroot remain external; no app/compiler/runtime byte-for-byte reproducibility is asserted. Gitiles can regenerate archive packaging: the recorded SHA-256 values pin the retained download bytes, while per-file inventories record source contents independently.

The release corresponding-source archive `tidy-v2.3.1-corresponding-source.tar.gz` includes authored application source, tests, wrapper/build/install materials, dependency manifests, exact native archives and full native sources, exact Java preferred-source JARs and metadata, conservative runtime base/patched sources and reconstruction inputs, complete original Android patches/recipes, and full notices/licenses. It excludes SDK/AVD installations, private configuration, signing keys, build products and the original 2.2.0 APK. Gradle/plugin/Maven tooling needs its normal resolution cache or repositories; this is not an entirely offline SDK or full compiler-source bundle. Verify the archive's contents and hashes during release packaging.

## Signing and reproducibility boundaries

Signing is optional. Supply all four environment variables `TIDY_KEYSTORE`, `TIDY_STORE_PASSWORD`, `TIDY_KEY_ALIAS`, `TIDY_KEY_PASSWORD`, or set `TIDY_SIGNING_PROPERTIES` to a private file **outside the checkout** containing `storeFile`, `storePassword`, `keyAlias`, `keyPassword`. Environment values take precedence. Never commit keys, passwords or private properties; keep the keystore outside the checkout and maintain a protected external/offline backup. The build rejects partial credentials. A recipient can build and sign a modified version with their own key; no official private key is needed or supplied. Android installation of a differently signed version requires uninstalling the existing package, after backing up media/settings.

The new release certificate SHA-256 is `27c165f0a6f13f8b01ed6628bd1a2e8f61daeb3b33438c6808f41f331aa45389` (`CN=Tidy Release, O=Tidy`). It is not the old debug certificate. No original signing key was recovered.

## Verification boundaries

The [Android CI workflow](../.github/workflows/android.yml) installs the SDK packages above on Ubuntu with JDK 17 and runs:

```sh
CMAKE_BUILD_PARALLEL_LEVEL=2 ./gradlew :app:testDebugUnitTest :app:assembleDebug :app:lintDebug --max-workers=2 --no-daemon --continue
```

The stable job name is **Android checks**. A 90-minute timeout and two Gradle/native workers accommodate compiling both native ABIs; source archives are fetched by CMake from immutable commit URLs and verified against SHA-256. Reports/test results are uploaded even if Gradle fails. The successful-run debug APK artifact is not an official signed release. This workflow executes no emulator, instrumentation or physical-device checks.

[CodeQL](../.github/workflows/codeql.yml) analyzes current Java source using the `java-kotlin` extractor with `build-mode: none`, separately from Android CI. Kotlin requires a traced build; it, JNI C++ and native codecs are not covered here. [Dependabot](../.github/dependabot.yml) proposes weekly Gradle/action updates without automatic merging. Native archive pins require manual review. Action references are immutable SHAs with version comments.

Manual verification includes custom instrumentation on disposable fixtures, Gallery readability/consent/lifecycle checks, and checking the exact final signed release APK's signature and ZIP/ELF alignment. CI success cannot establish these outcomes. Record artifact-specific observations, not inferred device passes.

Artifact-specific results and limits are recorded in [2.3.1 release notes](../releases/v2.3.1/RELEASE-NOTES.md), including generated-image Gallery checks, consent migration and actual dashboard/Gallery smoke. Android 11 timestamp boundaries require Android execution; a host test cannot prove them. Device measurements are observations, not latency guarantees or all-OEM coverage.

NDK 27.1 builds with `ANDROID_SUPPORT_FLEXIBLE_PAGE_SIZES=ON`. Check the final APK with `apksigner verify --verbose --print-certs` and `zipalign -c -P 16 4`, and inspect every ELF load segment's alignment. The release is non-debuggable, backup-disabled and has no INTERNET permission. Download APK, matching corresponding source and `SHA256SUMS.txt` together from the [v2.3.1 release page](https://github.com/faraajs/tidy/releases/tag/v2.3.1).

The separately extracted 2.3.0 source-bundle rebuild, anonymous download checks, unavailable-codec fixture and boot/theme exercises remain [historical release evidence](../releases/v2.3.0/RELEASE-NOTES.md), not verification of changed 2.3.1 behavior. No byte-identical app/compiler/runtime rebuild is claimed.
